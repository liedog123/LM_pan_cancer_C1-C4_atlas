## Using this environment guide

This is a dependency index for the **90 entrypoints in 15 workflows**, not an installation recipe or a tested environment lockfile. Choose the required branch from the [output/run-order map](../docs/result_output_mapping.md), then use its workflow README and example DCF. Only dependencies for that branch are relevant; some retained entrypoints also generate plots and therefore require their graphics dependencies even when a new figure renderer is not part of the delivery scope.

The public package has been checked in the author-selected **R 4.5.1** environment. Parsing, help and metadata-only configuration checks do not load the ordinary analysis dependencies or establish full execution compatibility. A small number of explicitly recorded synthetic helper tests use packages; those checks do not certify the entire module. A portable lockfile, clean installation and ordinary-run compatibility remain unverified.

## Important compatibility boundaries

- **GSVA:** inspected public scoring calls use `ssgseaParam` → `gsva`. No legacy expression/method call or automatic old/new GSVA adapter was found. Single-cell 14's layer/slot fallback extracts expression; it is not a GSVA-version adapter.
- **Seurat objects:** single-cell 02/04/05 access legacy RNA `@counts`/`@data`; 06/17/18 use `SeuratObject::Layers`/`LayerData`. Object deserialization alone does not establish assay compatibility, and automatic Assay5 conversion is not provided. Matching Seurat/SeuratObject class definitions may be needed even where the source does not explicitly load those namespaces.
- **Model dependencies:** retained robust edgeR/limma fits and limma `duplicateCorrelation` need compatible runtime dependencies, including statmod where applicable. Metadata checks do not exercise fitting or blocking.
- **fgsea:** preserve each source algorithm, ranking scope, seed and process setting. For example, single-cell 11 uses `fgseaMultilevel` with `nproc=4`, while 12 uses `fgseaSimple` with 1,000 permutations and `nproc=1`. CD8 09's internal `fgsea:::calcGseaStat` call is a version-sensitive curve-reconstruction interface; parsing does not test it.
- **CellChat:** single-cell 17/18 require a compatible API, `CellChatDB.human` and matching normalized RNA layers. A recorded CellChat version alone does not establish database identity or portable object compatibility.
- **System tools and graphics:** external `gzip` and `sha256sum` are required only where invoked. `tools::md5sum` and digest are different mechanisms, not replacements. Retained source plots need the selected Cairo/TIFF/PNG devices and fonts such as Arial. These were not probed during metadata checks.
